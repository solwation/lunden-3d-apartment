## Implementation and measured validation

A's wider outer corridor end joins the existing west passage; B's east corridor joins the stair hall through the basement-only hole z46.1…47.0, then turns north before the rising flight. Existing main-entry lobby work (#727) is retained. The new threshold/corridor rectangles have exact butt joins; Garage omits the niche/doorway floor where the single surroundings threshold slab covers it. New paving rectangles also meet without overlap. No additional exterior C door is invented.

- **56 actual-main assertions PASS**, `tools/basemententrytest.html`, with a real trusted mouse-start/PointerLock followed by the production E handler, actual raycast targets and physical Player movement. Closed leaves block, opening admits both routes at constant −3 m, side jambs stay solid, and return routes go outside. Touch checks invoke the real action-button handler with fixture-controlled touch mode; no physical phone was tested.
- **22 existing terrain assertions PASS**: the level/ramp/stair/drive/plinth portion of `terraintest.html` reused the loaded scene. Its global 5-cm whole-site sweep was not rerun. **6 focused actual-mesh opening/window assertions PASS**: both backplanes are clear, upper façades stay solid, and three existing mapped panes per house remain exposed. **84 total PASS, 0 FAIL** in this targeted final scope.
- After small final sensor/car-visibility edits, the actual updated Garage methods were imported into the retained main instance and the entry fixture rerun with fresh counters/closed-door preconditions. The final production courtyard builder rebuilt the generated shrub batch only: **16→12**, all retained matrices/colours exactly preserved, and actual instance bounds plus PLAYER.radius keep the paving clear. Door, floor and input target identities were retained. This avoided another cold apartment startup.
- Rendered before/after exterior, open and interior images are real 900×600 Chrome/SwiftShader frames. Clock 09:45; actual main steps with dt>0 settled the garage/day lighting before each final capture. Full quality/shadows were enabled through the test controller; antialiasing remains off in `&test=lazy`. These are not production FPS or physical-device measurements.
- Using `perfcount`'s main-screen draw instrumentation in that retained full-quality scene: A **96 calls / 490809 triangles**, B **118 / 586807**, below the ordinary 520 / 1000000 budget. Isolating the two-leaf exterior batch in the same scene gives **+1 main-screen draw / +48 triangles** at both views. These are an isolated batch toggle, not whole-issue before/after performance figures; shadow/mirror/environment passes are excluded. No new texture or dynamic light is introduced.

Before images use base `735817f`. The stored raw `renderer.info` screenshot counters are not used as a performance baseline because nested renders and sensor state can change them. No complete maximum test suite, physical-phone input or FPS claim.

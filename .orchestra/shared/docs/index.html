Value Proposition

Why a Conductor?

Agents left on their own over-plan, spawn helpers they don't need, rerun huge test suites repeatedly, and freeze waiting for manual confirmation. A conductor keeps one job in one place: decide, delegate, listen, deliver.

❌ Without a Conductor

  • ⚠️ Fragile babysitting: One endless chat session that wanders off, loses context, or gets stuck in repetitive loops.
  • ⚠️ Constant mid-task prompts: Agents pester you with "Should I do X or Y?" questions they could have decided with routine judgement.
  • ⚠️ Colliding checkouts: Multiple agents edit the same working tree, clobber shared git stashes, and overwrite each other's work.
  • ⚠️ Blind test reruns: Full test suites executed over and over "just in case", wasting tokens, context, and time.
  • ⚠️ "Should work" closures: Work marked as done without real verification, screenshots, or proof on the target branch.

🎼 With Dirigenten och orkestern

  • ✅ Unattended execution: You give one instruction or type /orkester; the queue runs completely autonomously.
  • ✅ Autonomous judgement: The conductor decides routine details. Genuine product questions land on the issue with clear options and recommendations.
  • ✅ Isolated worktrees: Each worker plays its part in its own dedicated worktree, on its own branch and ports, with automatic cleanup.
  • ✅ Risk-based verification: 2–3 checks tied specifically to the change's actual failure risks, then stop.
  • ✅ Evidence before delivery: Verified test results, links, diffs, and confirmation that the commit landed on remote main.
Orchestration Architecture

Who Plays What

A clean division of responsibilities prevents context bloat and ensures parallel efficiency.

Structured Delivery

The 5 Delivery Gates

Every change follows five rigorous, repeatable gates. No skipped verification, no mysterious branches left behind.

1

Planning

Write a sharp 5-line plan: outcome, boundary, 2–3 checks, smallest useful team, and integration owner. Claim work under Issueflow metadata.

2

Isolation

Each writing agent works in its own git worktree with dedicated ports. An orchestra-claim marker protects active work from early pruning.

3

Verification

Run agreed risk-based checks against a stable revision. No endless rerun loops; stop once evidence passes. Hard gates are never waived.

4

Review

The conductor reviews the combined diff once against acceptance criteria. Finished workers hand off via integration-ready to free slots.

5

Delivery

Deliver directly to main (or PR). Post completion evidence with revision, checks, and limitations. Automatic worktree prune at drain.

Get Started

Install in 2 Minutes

No runtime dependencies, npm packages, or background daemons. Plain Markdown files in your repository.

Option 1: Ask your AI agent to install it (Easiest)

Copy and paste this prompt into Claude Code, Codex, Antigravity, or your preferred agent: 

Install the orchestra in this repository by following
https://github.com/solwation/dirigenten-och-orkestern/blob/main/INSTALL.md
and fill in the project policy from what you know about this repository.

Option 2: Install by hand via Git subtree

Vendors the core workflow into .orchestra/shared: 

git subtree add --prefix=.orchestra/shared \
  https://github.com/solwation/dirigenten-och-orkestern.git v0.12.0 --squash
cp .orchestra/shared/PROJECT.example.md .orchestra/project.md
Architecture Reference

Core Workflow Files

Everything is transparent, versioned, and inspectable Markdown in your project.

File Role & Description
ORCHESTRA.md The conductor's score: read maps, delivery gates, isolation rules, and verification standards.
WORKER.md The compact brief given to worker agents: role boundaries, evidence collection, and handoff.
COORDINATION.md Queue coordination: bounded passes, session naming, priority ordering, and idle watches.
ISSUE-WORKFLOW.md Authority for GitHub labels, state transitions, and integration-ready handoffs via Issueflow.
PROJECT.example.md Template for project-specific settings, required checks, and custom phase hooks.
INSTALL.md Complete installation guide, slash command adapters, updates, and release discovery.
